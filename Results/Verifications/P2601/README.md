**最终选定 PR 4（260818）为本题冠军**。

### 相关基础数据

**正确性**（判据：赛题详情页「所有算子需通过精度验证」「支持 VLEN 128/256/512 自适应」）：

- 完整 API 套件以 `KLEIDICV_BUILD_FULL_API_TESTS=ON` 显式开启（该开关默认 OFF，
  开启前的冒烟测试仅 8 项，曾致证据强度误判，详见卷1 第三章）。
- VLEN 256/512 无硬件可用，经 QEMU 用户态模拟（`-cpu rv64,v=true,vlen=N`）补齐；
  三档崩溃点比对用于区分缺陷与向量长度无关的内存错误。

**I420／YV12 布局专项**（2026-09-22 测试，09-23 复现，计数吻合）：

| 测试组 | PR 3 RVV | PR 3 标量 | PR 4 RVV | PR 4 标量 |
|---|---:|---:|---:|---:|
| 原始参数解码（160 组） | 64/96 | 64/96 | 160/0 | 160/0 |
| 偶数尺寸解码（480 组） | 400/80 | 400/80 | 480/0 | 480/0 |
| 偶数尺寸编码布局（480 组） | 400/80 | 400/80 | 400/80 | 400/80 |

要点：该缺陷与向量化无关（标量档结果与 RVV 档逐字节相同）；编码布局两家同样失败；
该测试暴露了「自带套件全过不等于与原版行为一致」的方法盲区。

### 不同二进制的比较

PR 2 的两处实质问题均经双重佐证：RVV 档崩溃（`RemapF32/0.RandomNoPadding`，signal 11，
三档 VLEN 崩溃点相同）经真机两次、QEMU 三档复现；标量档缺失符号
（`kleidicv_count_nonzeros_u8`、`kleidicv::neon::min_max_loc` 等）另经
`kleidicv-benchmark` 目标独立复现，证明缺陷在库本身。

## 流程

1. 形式审查（冻结 SHA 与归档核验）
2. 按各提交说明文件复现构建（PR 1 走其自带 `riscv/` 树与工具链文件）

4. benchmark 数据采集（`clang-format` 检查另见卷1 4.3.3 代码规范一节）
5. I420 布局专项（以自有归档源码复现，整树比对零差异）
